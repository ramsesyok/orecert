# 2026-09 セキュリティ・不具合修正記録

2026-09-22の実装レビューに基づき、2026-09-23に修正・検証した記録です。

## 合意した仕様

- P12は安全なAES方式を既定とし、旧環境向け3DES方式は`--legacy`で明示選択する。
- verifyは署名付きローカルCRLを既定で検証する。欠落・破損・署名不一致・期限切れを失敗とし、`--skip-crl`でのみ省略する。
- 暗号化PEMは幅広いアプリとの互換性を優先し、PKCS#8 / PBES2 / AES-256-CBC / PBKDF2-HMAC-SHA-256を使う。

## 検証結果

- 不具合を再現するテストの失敗を確認してから修正した。
- `go test ./... -count=1 -shuffle=on -coverpkg=./... -coverprofile=coverage.out`: 成功。
- 全ブロックを統合したstatement coverage: **92.24%（784/850）**。`scripts/check-coverage.ps1`で90%以上を要求。
- `go vet ./...`: 成功。

- govulncheck v1.8.0: 到達可能な脆弱性0件。import対象パッケージも0件。モジュール単位では未使用の`golang.org/x/crypto/openpgp`にGO-2026-5932が報告されるが、orecertはこのパッケージを使用していない。
- OpenSSL: RSA/ECDSA/Ed25519の暗号化PKCS#8の復号・鍵検査、P12読み込み、CA＋CRL検証が成功。P12のPBES2/AES-256-CBC/SHA-256/600,000反復を確認。
- Java 17.0.2: 3アルゴリズムのP12/JKSを読み込み、秘密鍵を取り出し、署名と証明書公開鍵による検証に成功。2枚の証明書チェーンを確認。
- Windows/.NET: RSA/ECDSAのP12をEphemeralKeySetで読み込み、秘密鍵を保持することを確認。証明書ストアへの登録はしていない。

Linuxはクロスビルドまでをローカルで確認した。Linuxの実行テストとGitHub Actions自体の実行はCIに委ねる。各サーバ製品でのTLS通信、WindowsでのEd25519利用、外部アプリへのCRL配布・信頼設定は今回の検証範囲外。

## 制限・運用上の扱い

- CA鍵は平文PEMのままアクセス権限で保護する。発行鍵はencrypt_keyの指定に従い、未指定時は平文。
- 証明書／CAの自動信頼登録はしない。CRL生成と実際のサーバ／クライアントでの失効適用は別作業。
- 電源断・強制終了・同じ出力先への並行操作は複数ファイル更新の保証外。
- 旧仕様の詳細な終了コードとJSONエラー形式は未実装。現在の失敗は終了コード1。
- 旧バンドルや平文鍵を自動で書き換えない。移行手順に従って必要なものを再発行・再バンドルする。

操作例と移行手順は[利用ガイド](README-ja.md)を参照してください。
